Data engineering project

Assembly Line Data Pipeline

I built an end-to-end pipeline for simulated vehicle assembly data. It creates messy machine exports, cleans them with Python and Pandas, loads PostgreSQL, and shows the results in a live-updating dashboard.

View the GitHub repository See project releases

What I built

The project simulates station events, quality defects, and downtime. The ETL step removes duplicate events and rejects records with missing timestamps or non-positive cycle times. FastAPI and Streamlit display line metrics, and a scheduled GitHub Actions job can email a daily 24-hour summary.

How the data moves

Python data generator→ Raw CSV files→ Pandas cleaning→ PostgreSQL→ FastAPI→ Streamlit dashboard

Docker Compose runs PostgreSQL, the API, and the dashboard together. I run the generate, clean, and load commands from the project’s Python environment.

What I learned

  • Dirty data rules can overlap. One missing timestamp exposed a bug in my negative-cycle fault injection.
  • Later “file not found” errors can be consequences of an earlier failed pipeline step.
  • Docker’s host port can conflict with software already running on my computer, so I mapped PostgreSQL to port 5433.
  • A Python simulator generates five new station events every 15 seconds, while making it clear that no real factory feed is connected.
  • A scheduled job can email a fresh synthetic 24-hour report. It does not read private dashboard session data.
  • Metric definitions and denominators need to be stated clearly. The OEE-style number is only a quality proxy.

Tools and next steps

Tools: Python, Pandas, PostgreSQL, SQL, FastAPI, Streamlit, Docker Compose, pytest, and GitHub Actions.

Next: measure representative SQL queries on a larger dataset, validate defect and downtime records, and improve incremental loading.
